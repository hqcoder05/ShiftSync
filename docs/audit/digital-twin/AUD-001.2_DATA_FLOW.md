## 3. Kiến trúc quản lý trạng thái Frontend (Frontend State Architecture)

Phân hệ Digital Twin trên Web (`ShiftSync-Web`) phân tách ranh giới dữ liệu thành 5 tầng trạng thái riêng biệt:

```
[1. Local Three.js Scene State] (Mesh, Transforms, Raycaster, Materials)
           │ (Đồng bộ qua Animation Loop & Event Handlers)
           ▼
[2. Simulation State (Zustand)] (simulationStore.js: simulatedStaff, simulatedDiff, history)
           │ (Cô lập hoàn toàn, không gọi API khi người dùng đang thao tác kéo thả)
           ▼
[3. Request Payload State] (Dựng payload từ simulatedDiff trong handleApplySimulation)
           │ (Gửi qua Axios HTTP Client)
           ▼
[4. Persisted Backend State] (PostgreSQL tables: store_layouts, store_zones, shift_assignment)
           │ (Phản hồi HTTP 200/201/409/500)
           ▼
[5. Reconciled React UI State] (React useState trong SchedulePage & StoresPage)
```

### 3.1. Phân loại chi tiết các trạng thái:
- **Local Three.js Scene State:** Quản lý tọa độ vật thể 3D, mesh nhân vật (`StylizedAvatars.js`), quầy kệ (`FurnitureBuilder.js`), camera góc nhìn (`CameraController.js`). Trạng thái này chỉ tồn tại trong bộ nhớ GPU/WebGL context.
- **Simulation-Only State:** Được đóng gói trong Zustand store [`simulationStore.js`](file:///d:/ThucTapTotNghiep/ShiftSync/ShiftSync-Web/src/features/spatial-workspace/simulation/simulationStore.js). Gồm snapshot dữ liệu gốc `productionSnapshot`, danh sách nhân sự mô phỏng `simulatedStaff`, nhật ký thay đổi `simulatedDiff`, và ngăn xếp Undo/Redo `history[]`.
- **Request Payload State:** Danh sách các lệnh thay đổi (`diffList`) được chuyển thành payload gửi qua `assignStaffToShift` hoặc `removeStaffFromShift`.
- **Persisted Backend State:** Bản ghi lưu trữ vĩnh viễn trong các bảng CSDL PostgreSQL (`store_layouts`, `store_zones`, `workstations`, `shift_assignment`).
- **Reconciled UI State:** Dữ liệu React state tại [`SchedulePage.jsx`](file:///d:/ThucTapTotNghiep/ShiftSync/ShiftSync-Web/src/pages/SchedulePage.jsx) và [`Store3DManager.jsx`](file:///d:/ThucTapTotNghiep/ShiftSync/ShiftSync-Web/src/components/spatial/Store3DManager.jsx) được cập nhật lại khi nhận phản hồi từ backend.

* **Định nghĩa hàm API:** [`shiftService.js:43-48`](file:///d:/ThucTapTotNghiep/ShiftSync/ShiftSync-Web/src/services/shiftService.js#L43-L48):

* **Xử lý tại Backend:** [`ShiftAssignmentService.java:137-149`](file:///d:/ThucTapTotNghiep/ShiftSync/shiftsync-backend/src/main/java/com/shiftsync/shift/service/ShiftAssignmentService.java#L137-L149):

* **Hậu quả thực tế:**
  1. Khi người dùng kéo thả đổi vị trí nhân sự, `diff.type` là `'TRANSFER'`.
  2. `SpatialWorkspace.jsx` gọi `assignStaffToShift` mà **hoàn toàn quên truyền tham số thứ 4 (`diff.toZoneId`)**.
  3. Tham số `zoneId` bị `undefined`, payload gửi lên là `{ staffId }` (không có `zoneId`).
  4. Backend nhận thấy nhân viên này đã có trong ca trực, nhưng vì `requestedZoneId == null` nên backend ném lỗi **HTTP 409 CONFLICT: "Staff is already assigned to this shift"**.
  5. Khối `catch` tại dòng 796 nuốt chửng lỗi bằng `console.warn`.
  6. Dòng 804 gọi `exitSimulation()`, hủy bỏ toàn bộ trạng thái thử nghiệm và tải lại dữ liệu từ server.
  7. **Kết quả:** Thao tác điều chuyển không gian của quản lý bị hủy bỏ hoàn toàn mà người dùng không hề được thông báo lỗi.

## 6. Bảng chuyển đổi trạng thái (State Transition Table)

| Thao tác người dùng | Trạng thái nguồn | Trạng thái cục bộ (Client) | Payload gửi Backend | Trạng thái lưu CSDL (PostgreSQL) | Hành vi điều hòa (Reconciliation) |
|---|---|---|---|---|---|
| **Vào phòng mô phỏng** | Production | `isSimulating=true`, snapshot cloned | Không có | Không đổi | Hiển thị banner cam "Phòng thử nghiệm" |
| **Kéo thả nhân sự (TRANSFER)** | Simulated A | Chuyển sang Phân khu B, tạo diff `TRANSFER` | `{ staffId }` *(Thiếu `zoneId`!)* | **Không đổi (Lỗi 409 nuốt lỗi)** | Modal đóng, reset về snapshot cũ |
| **Gán mới nhân viên (ASSIGN)** | Unassigned | Gán vào Phân khu B, tạo diff `ASSIGN` | `{ staffId }` *(Thiếu `zoneId`!)* | Backend tự động map Zone theo Skill | Cập nhật bảng ca trực sau khi tải lại |
| **Rút nhân viên (REMOVE)** | Simulated B | Bỏ nhân viên, tạo diff `REMOVE` | `DELETE .../assignments/{staffId}` | Bản ghi chuyển `deleted=true` (Soft delete) | Nhân viên biến mất khỏi bản đồ 3D |
| **Đổi vị trí 2 người (SWAP)** | Sim A & Sim B | Đổi chéo 2 nhân viên, tạo diff `SWAP` | **Không có (Bị bỏ rơi trong code)** | Không đổi | Bị mất sau khi thoát phòng mô phỏng |
| **Lưu kích thước (Dimensions)** | Layout cũ | Form state cập nhật | `POST /layout` `{length, width, height}` | Bảng `store_layouts` cập nhật | Gọi `loadSpatialData()`, vẽ lại sàn 3D |
| **Thêm khu vực (Add Zone)** | Danh sách zone cũ | Form modal | `POST /zones` `{name, x, y, z, capacity...}` | Thêm bản ghi mới trong `store_zones` | Thêm Mesh khu vực và decal HUD trên sàn |

## 7. Ranh giới giao dịch & Lỗi phân mảnh dữ liệu (Transaction & Partial Commit)

Khi quản lý áp dụng nhiều thay đổi trong `simulatedDiff` (ví dụ: 5 thao tác):
- Frontend dùng vòng lặp `for ... of` gửi 5 HTTP request độc lập.
- Mỗi HTTP request là một giao dịch `@Transactional` độc lập trên Spring Boot.
- Nếu request số 1, 2 thành công nhưng request số 3 thất bại (ví dụ: mất mạng hoặc vi phạm ràng buộc):
  - Request 1 và 2 **không thể rollback**.
  - Request 3, 4, 5 bị hủy hoặc lỗi.
  - CSDL rơi vào trạng thái phân mảnh dở dang (partial commit).
  - Không có cơ chế bồi hoàn (Compensating Transaction) hay Transaction Batch API trên tầng backend.
